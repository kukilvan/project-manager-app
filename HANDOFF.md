## 1. Зачем приложение и кто им пользуется

**Иван** — полевой техник-монтажник слаботочных систем в Израиле: СКУД, охрана, камеры, контроллеры, Wi-Fi, кабели.
Он работает по найму у человека, который находит объекты и платит зарплату, и планирует открыть своё дело (эсек).
Он не программист: пишет по-русски, всё проверяет руками на телефоне.

Чем приложение заменило прежний способ работы:
- раньше были заметки на iPhone, потом AppSheet поверх Google Таблицы «Полевой журнал». AppSheet не трогаем, Иван решит его судьбу сам;
- теперь это своё PWA: ставится на экран iPhone, работает и в браузере на Windows.

Что в нём ведётся по объекту:
- **точки** с типом, шкафом, этажом, кабелями, длиной, портами панели, серийником и MAC;
- **ежедневный отчёт «дох»** по-русски с текстом на иврите. Его Иван каждый день отправляет работодателю в WhatsApp;
- **протяжки и метраж**, **шкафы и шильют** (раскладка панелей и наклейки портов);
- **план**: чертёж заказчика («тохнит») с точками, раскрашенными по статусу;
- **таблицы для руководства** на иврите в Google Таблицах, без длин кабелей;
- **месячный отчёт**: сумма дохов за месяц, начальник выставляет по нему счёт заказчику.

Кто пользуется:
- **Иван.** Основной пользователь, с iPhone (значок на главном экране) и с компьютера на Windows.
- **Помощник Ивана и коллеги**, в том числе узбекоязычные: иврита и профессиональных терминов они не знают. Поэтому есть руководство, тур и «Словарик».
  Коллеги работают со своими Google-аккаунтами в общем проекте. У всех равные права, но видно, кто что и когда изменил, и всё можно откатить.
- **Руководство и заказчик** приложение не открывают. Они видят только таблицы Google на иврите, которые приложение собирает само.
- С версии 1.1 сайт общий: любой монтажник может подключить свою базу Firebase или работать в режиме «на устройстве».
  По факту пользователь пока почти один — Иван.

Главное требование Ивана: **всё должно работать без интернета, от начала до конца**. На объектах связи часто нет.
Интернет нужен только для того, чтобы выгрузить и синхронизировать копию данных.

Текущий рабочий проект в базе — «Мегасон Бэйт Шемеш» (около 750 точек, шкафы FA, FC и другие). До него был Mega Or (Модиин).

| авизар | устройство, аксессуар на двери (אביזר) |
| протяжка | прокладка кабеля |
| хивут | расшивка, подключение (חיווט): «хивут кистона на шетахе» (у точки), «хивут в шкафу» |
| кистон | keystone-разъём |
| шетах | поле, сторона точки (שטח) |
| шилют | наклейки с названиями точек на портах панели (שילוט) |
| метаэм пас-дин | адаптер на DIN-рейку (מתאם פס דין) |
| орэх | длина (אורך) |

| 6005 | многожильный сигнальный кабель для дверей и датчиков |
| Fluke | проверка кабеля тестером |
| шкаф | серверный шкаф с 24-портовыми панелями. Точки группируются по шкафу, часто по префиксу обозначения |

## 3. Что уже сделано

Версии зафиксированы ветками `release-*`. Подробности и тексты для людей — в руководстве внутри приложения (`src/app/views/guide.js`).

**Версия 1.0 (до 23.10.2026, тогда приложение называлось «Полевой журнал»):**
- **Основа.** Синхронизация через Firebase: вход через Google, Firestore с офлайн-кэшем. Импорт данных из AppSheet.
  История изменений и откат: мягкое удаление, откат записи и откат «изменений пользователя за период». Участники проекта.
- **Работа на объекте.** Точки и карточка точки, массовые действия, «Что осталось», полоски готовности по шкафам.
  Сканер серийника и MAC (Code128, QR, DataMatrix), выгрузка в Excel, простои по виновникам за месяц, светлая тема, «Словарик».
- **Обслуживание.** Индикатор «ждут отправки». Резервная копия на Диск. Автокопия на сервере раз в 2 дня (GitHub Actions).
  Архив проектов и удаление навсегда через год. Экономия чтений Firestore.
- **Таблицы для руководства** с профилями (основная и расширенная), на иврите или по-русски, ночное обновление с сервера.
- **Модель «точка из устройств»** (`src/domain/compose.js`). Цепочка: кабель (вид и работы на каждый кабель) → устройство (кабели и свои работы) → тип точки (состав по умолчанию и работы на всю точку) → свой состав у точки.
  Задачи и статусы точки считаются из состава.
- **Разбор тохнита прямо в приложении, без ИИ.** Каталог подписей, вопросы по неизвестным группам, значки без номеров, нумерация по областям.
  Для Claude есть отдельный инструмент `tools/tohnit/` (Python и навык «разбор тохнита»).
- **План.** Чертёж хранится на Google Диске и копией на устройстве. Есть фильтры, слои, работа на выбранные точки, «➕ Точка на плане», значки типов, «📄 PDF с номерами».
- **Конфигурации дверей**, общий пул справочников, протяжки с метражом, шкафы и шильют.

**Версия 1.1 (23.10.2026), «один сайт для всех»:**
- в коде нет настроек Firebase. При первом запуске мастер помогает создать свою базу. Другой вариант — режим «на устройстве» (данные только в телефоне, IndexedDB);
- коллеги подключаются по «ссылке для подключения» (`?connect=…`);
- администратор базы — первый вошедший (документ `meta/admin`). Он ведёт общий пул и список разрешённых почт;
- стартовый набор справочников `src/data/starter-pool.json` раз в неделю обновляется из автокопии сам;
- Google Диск работает и без Firebase, через общий OAuth-клиент;
- переименование в «Менеджер проектов», репозиторий `project-manager-app`.

**Версия 1.2 (24.10.2026):** интерфейс на русском, английском и иврите (иврит справа налево).

**После 1.2 (номер в `package.json` остался `1.2.0`; сборку видно в «Журнале событий», строка «Сборка»):**
- **Протяжка.** Кнопка «Предыдущая». Чеклист «выбрать все». Точки без кабеля не требуют метража. Пара или тройка на одной отметке получает один метраж. Фильтр по типу на плане.
- **Значок и телефон.** Новый значок (файлы `*-v2.png`). Двойное касание не увеличивает экран, выделение текста на телефоне отключено.
- **Дох.** Одинаковые работы за день суммируются. Время — в часах и минутах.
- **Быстрый запуск без ожидания сети.** Вход и права администратора проверяются в фоне (`src/firebase.js`, `src/main.js`).
- **Работа без связи.** Новое и изменённое видно сразу, не дожидаясь выгрузки (`src/app/repo.js`: слушатель кэша).
- **«🔄 Новая версия чертежа»** (`src/domain/sheetfit.js`, `src/app/views/planversion.js`). Точки переносятся на обновлённый тохнит другого размера
  по преобразованию «сдвиг + масштаб + поворот», найденному по общим подписям. Что не нашлось, уходит в окно «⚠ Проверить после новой версии».
- **«🔀 Одинаковые точки в разном виде»** (`src/domain/merge.js`, `src/app/views/pointmerge.js`). Двойная `FC/B05-06` и одинарные `FC/B05` + `FC/B06` объединяются
  с переносом работ, журнала, протяжек и метража. Одинарные подряд на одной отметке без двойной предлагается сделать двойной.
- **Кабели по номеру точки.** Одинарная точка cat7 — 1 кабель, двойная — 2, тройная — 3 (`cablesByLabel` в `merge.js`).
  Разбор и импорт ставят это сам. Для уже добавленных точек есть кнопка «🔌 Кабели не по номеру точки».
- **Свой набор работ на точках** (`point.ownWorks`, раздел «Работы на точках» в окне «✏️ Изменить» для одной точки и для группы).
  Работу можно добавить, убрать, задать количество на точку или на каждый кабель. Пример: метаэм пас-дин — у двойного бакара 2, у одинарного 1.
  Код: `src/domain/ownworks.js`, `applyOwnWorks` в `compose.js`, `src/app/views/ownworks.js`.

Тесты: `npm test`, 144 теста на `node:test`. Это чистая логика из `src/domain` и серверные скрипты.

## 5. Важные решения и почему так

### Платформа и деньги
- **PWA, а не приложение в App Store.** Нет аккаунта разработчика Apple, и платить за него Иван не хочет. Сайт на **GitHub Pages**, не на Firebase Hosting.
- **Firebase на бесплатном плане (Spark).** Иван не хочет привязывать банковскую карту, поэтому Blaze не подключаем.
  Отсюда лимит **50 000 чтений в сутки** (сброс около 10:00 по Израилю, это полночь по тихоокеанскому времени).
  Отсюда же и собственная автокопия: штатные бэкапы Firestore есть только на платном плане.
- **Экономия чтений — постоянное требование.** После первой загрузки читаются только изменения (`updatedAtServer`).
  Полная сверка — раз в неделю, в субботу (`src/domain/sync.js`). Автокопия на сервере тоже читает только изменённое, полностью — раз в неделю.
  Новое устройство при первой загрузке читает весь проект (в октябре это было около 2200 документов, сейчас данных больше).

### Данные и доступ
- **Вход только через Google.** Вход по паролю не делаем (решение Ивана от 10.10). Человек без Gmail создаёт Google-аккаунт на свою почту.
- **Ролей нет.** Все участники проекта равны. Защита — история изменений и откат.
- **Удалённое хранится год,** потом ночная задача удаляет его навсегда (`scripts/server-cleanup.mjs`, не больше 5000 документов за запуск).
- **Один сайт для всех (1.1).** Каждый подключает свой Firebase или работает «на устройстве». Данные Ивана в коде не живут.
- **Рабочие данные, чертежи заказчиков и ключи в репозиторий не кладём никогда.** Репозиторий публичный.
  Эталонные чертежи для `scripts/tohnit-eval.mjs` лежат вне репозитория.

### Язык
- Интерфейс на трёх языках. Язык выбирается по телефону **только у новых людей**: у кого уже есть данные, остаётся русский.
- По-русски всегда остаются «Журнал событий», таблицы для руководства (они на иврите или по-русски, по профилю) и имена папок на Диске.
- Иван пишет по-русски. Иврит нужен только в дохе, таблицах для руководства и названиях справочников (`nameHe`).

### Таблицы для руководства
- Таблица новая, не по старому шаблону. В ней только значения, без формул. Длин кабелей нет.
- Профили настраиваются чек-листами: шкафы, типы, статусы, столбцы.
- Ночью их обновляет сервер (`server-tables.yml`). Новых файлов сервер не создаёт, а доступ к файлу получает при ручном «Обновить» в приложении.

### Модель точек
- **«Точка из устройств»** заменила ручное поле «cat7×1» — первую попытку, от неё отказались.
- Хивут кистона и хивут в шкафу — **разные работы**.
- Протяжку точки с несколькими видами кабеля отмечают по каждому виду отдельно, чтобы не забыть дополнительный cat7.
- `point.cableOverride` — свои кабели точки целиком.
- **Кабели по номеру — правило по умолчанию,** исключения Иван правит вручную. Распространяется только на типы, у которых по составу один вид кабеля и это cat7.
  Двери (6005×3) правило не трогает.
- **Свой набор работ (`ownWorks`) — поверх типа, устройств и кабелей,** сами они не меняются. Формат: `[{ workId, qty, per? }]`, где `qty: 0` — работа убрана, `per: 'cable'` — на каждый кабель.
  Протяжку так не меняют: она идёт от кабелей. Для старой схемы типов (тип без состава) свой набор не работает.

### Тохнит
- Разбор идёт по **текстовому слою PDF** (подписи с цветом, шрифтом и размером), а не распознаванием картинки.
  ИИ или человек решает только, какие группы подписей — точки и какого типа.
- Цель — автономный разбор в приложении без ИИ, с каталогом подписей, который правится в самом приложении.
  Точность важнее количества вопросов: 5–10 вопросов кнопками на новом чертеже — нормально.
- Допустимо несколько пропусков на сотни точек. Недопустимы десятки пропусков и мусор (высоты вроде H240, номера помещений, размеры).
- Правило нумерации значков без номеров: каждый тип нумеруется отдельно с 1, слева направо, соседи получают подряд идущие номера.
  Большой лист делится на логические части, и нумерация в следующей части **продолжается**, а не начинается заново.
- **Новая версия чертежа** (ответы Ивана):
  - точка, которой нет на новом листе, остаётся и помечается;
  - сдвинутые точки остаются, Иван решает сам;
  - старый лист остаётся видимым;
  - новые значки сразу попадают в мастер.

### От чего отказались
- **Решения Ивана:**
  - копирование вчерашнего дня (И6), «любимые наборы работ» (И7), напоминание «дох не заполнен» (И8);
  - трассы и длины на плане, шкафы на плане;
  - Blaze, Firebase Hosting, нативное приложение и аккаунт разработчика Apple;
  - снимать квартиры LiDAR'ом своими силами — нашлось готовое приложение OpenPlan3D Capture;
  - ручное поле «cat7×1».
- **Не получилось технически:** распознавание MAC с фото. На наклейках Hikvision MAC напечатан только текстом, а распознавание мелкого текста ненадёжно, поэтому MAC вводят вручную.

## 6. Чего нет в README про устройство кода

- **`src/domain/`** — чистая логика без браузера, покрыта тестами: статусы, состав точек, дох, протяжки, шкафы, разбор импорта, перенос листа, объединение.
  **`src/app/`** — хранилище, синхронизация, Google. **`src/app/views/`** — экраны. **`src/tohnit/`** — разбор PDF (mupdf в фоновом потоке, `worker.js`).
- **Хранилище** (`src/app/repo.js`) имеет один интерфейс и три реализации:
  - Firestore;
  - память (`?mem=1`, для проверок);
  - память с записью в IndexedDB (режим «на устройстве», `localdb.js`).
  Все записи идут через `repo.save(pid, ops)`, а `repo.js` сам ставит, кто и когда изменил, и пишет историю.
- **Firestore:**
  - `projects/{pid}` (поля `memberUids`, `invitedEmails`) с подколлекциями из `COLLECTIONS` в `repo.js` и `history`;
  - `pool_types`, `pool_devices`, `pool_cables`, `pool_catalog`, `pool_manuals`, `pool_doorcfg`, `pool_inbox`;
  - `allowed/{email}`, `users/{uid}/…`, `meta/admin`.
  Правила — `firestore.rules`, а `firestore.open.rules` получается из них функцией `openRules`, тест сверяет одно с другим.
  В id документа нельзя `/`, поэтому есть `docKey()`.
- **Журнал работ.** Строка журнала = точка × работа. Id строк: `${entryId}_${pointId}` — из записи доха, `edit_${pointId}_${workId}` — правка без записи.
  `entry.portQty: [{id, v}]` — своё количество на точку (например, шилют части портов).
  Задача точки закрывается **одной** строкой журнала целиком: поле `done` логическое. Количество идёт в «итог шт» доха через `taskQty`.
- **Чертежи** лежат в `project.drawings`. Писать только через `patchDrawings(pid, fn)` в `src/app/drawings.js`: иначе старый снимок перезапишет свежий список.
- **Переводы.** Словари `src/i18n/src/*.json` в формате `{ "русская строка": ["en", "he"] }`.
  Собираются командой `node scripts/i18n-build.mjs` в `src/i18n/en.json` и `src/i18n/he.json` (оба файла в git). Шаблоны со вставками пишутся с `{}`.
  Найти непереведённые строки: `node scripts/i18n-extract.mjs --json out.json` и сравнить со словарями.
  У старых строк журнала событий и логов перевода может не быть — это нормально.

## 7. Известные ошибки, грабли и странности

**Firebase и сеть**
- **Лимит 50 000 чтений в сутки.** Если его съесть (например, полной копией или экраном «История изменений», это до 2000 записей за открытие), вечером падают автокопия и таблицы: `RESOURCE_EXHAUSTED`.
  Повтор таблиц в 07:20 UTC срабатывает, только если ночной запуск не удался.
- **Запрос изменений (`updatedAtServer > …`) не видит офлайн-записи.** У них серверное время ещё не проставлено.
  Поэтому интерфейс строится от слушателя кэша (`onSnapshot(..., { source: 'cache' })`), а запрос изменений только наполняет кэш. Не ломать это разделение.
- **Быстрый запуск.** Если Иван уже входил (`pm.authCached`), `initializeAuth` создаётся без `popupRedirectResolver`.
  Поэтому **любой** `signInWithPopup`, `signInWithRedirect`, `getRedirectResult` или `reauthenticateWithPopup` обязан получать `browserPopupRedirectResolver` явно.
  Иначе будет `auth/argument-error`: так ломался доступ к Диску.
- **В режиме `?mem=1` слушатели синхронные.** Гонки асинхронного Firestore там не воспроизводятся.
  Пример — ошибка, когда новый чертёж пропадал из-за старого снимка проекта. Такие места нужно продумывать по коду.

**iPhone и интерфейс**
- **iPhone держит старый значок,** пока файл не переименуешь (поэтому `*-v2.png`, ссылки с `%BASE_URL%` в `index.html`).
- **Двойное касание увеличивало экран.** Решено тремя мерами: `touch-action: manipulation`, перехватом второго касания (`src/app/nodoubletap.js`) и отключением выделения текста на сенсорных экранах.
  `maximum-scale=1` в viewport тоже стоит.
- **Клавиатура iPhone закрывала поля ввода.** Окна подгоняются под `visualViewport` (`src/app/keyboard.js`).
- **Иврит в мобильном Google Sheets показывается слева направо,** на компьютере — справа налево. Это особенность приложения Google, а не наша ошибка.
- **Локаль таблиц руководства `ru_RU`:** в формулах условного форматирования разделитель `;`, а не `,`.
- **`h()` выводит `null` текстом,** если передать `null` в `replaceChildren(...)`. Сначала фильтровать: `.filter(Boolean)`.
- **Своё поле формы в `formModal`** (`type: 'custom'`): события ввода всплывают, и `update(v)` вызывается на каждое нажатие клавиши.
  Поле должно перерисовываться, только когда реально изменились нужные значения (сравнивать подпись значений).
  Значения других своих полей, загруженные в том же обновлении, читать после него. Пример — `queueMicrotask` в `src/app/views/ownworks.js`.

**Модель данных**
- **Две схемы типов.** Старая: тип без `devices` и `cables`, в нём `defaultCable` и `defaultCables`, статусы считаются в `status.js`.
  Составная: в типе есть `devices` или `cables`, задачи считаются в `compose.js`. В проекте Ивана все типы составные, но `seed.js` содержит старые.
  `type.cables` — это **кабели самой точки** (не устройств).
- **`RANGE` в `merge.js`** считает диапазон по последним цифрам: `B05-06` → 2. Ограничение — от 1 до 8, иначе правило «по номеру» не применяется.
- **PDF-подписи.** Две подписи бывают одним текстовым фрагментом (`FC/B09-10 FC/B11-12`). Их делит `splitLabelRuns` в `src/tohnit/engine.js`.

**GitHub и окружение**
- **Теги из облачной сессии в GitHub не пушатся** (прокси запрещает). Поэтому отметки делаются ветками и пустыми коммитами.
- **Бот `pool-bot` по понедельникам в 09:00 UTC может закоммитить в `main`** «Стартовый набор: обновлён из общего пула». Перед пушем делать `git pull --rebase`.
- **GitHub отключает расписание после 60 дней без активности.** Задачи сами продлевают его в конце запуска.
- **В Playwright первым делом всплывает тур.** Нажать «Не напоминать», иначе он перекрывает клики.

## 8. Как запускать, проверять и выкладывать

```
npm ci                      # Node.js 22
npm test                    # тесты (node:test), должны быть зелёными: без них не будет выкладки
npx vite build              # сборка в dist/
npx vite preview --port 4176   # локально; открыть http://localhost:4176/project-manager-app/?mem=1
```

- **`?mem=1`** — тестовый режим. Данные в памяти, вход-заглушка (`test@example.com`, другой адрес — `&memEmail=…`), Google заменён заглушкой (`window.__gcalls`).
  `window.__pzTest = { state, getRepo, currentProject, setCurrentProject }` даёт доступ к данным из Playwright.
  Обычный приём: создать проект через `__pzTest.getRepo().createProject(...)` и залить в него копию проекта Ивана.
  Копия — это файл «резервная копия» в формате `polevoy-import-1` с полями `reference`, `projectData`, `points`, `journal`, `days`, `entries`, `pulls`.
  Затем нажимать кнопки и делать скриншоты на ширине телефона, 420 px.
  Копии данных Ивана в репозиторий не класть: держать только в рабочей папке сессии.
- **Chromium и Playwright в облачной сессии уже установлены.** `require('playwright')`, `chromium.launch()`. Ставить заново не нужно.
- **Выкладка:** любой пуш в `main` запускает `.github/workflows/pages.yml` (`npm ci` → `npm test` → `npm run build` → GitHub Pages). Обычно это 1–2 минуты.
  Ход выкладки видно так: `gh api "repos/kukilvan/project-manager-app/actions/runs?per_page=1"`.
  Приложение у людей обновляется само (service worker с `autoUpdate`). При необходимости — пункт меню «🔄 Обновить приложение (версия …, сборка …)» в ☰ → Настройки.
- **Серверные задачи** (`.github/workflows`):
  - `server-backup.yml` — раз в 2 дня в 08:30 UTC. Копия в закрытый `kukilvan/polevoy-backups` и zip на Google Диск, затем удаление навсегда старого удалённого;
  - `server-tables.yml` — каждую ночь в 00:00 UTC и повтор в 07:20 UTC;
  - `export-pool.yml` — по понедельникам, стартовый набор из автокопии.
  Все запускаются и вручную (`workflow_dispatch`).
- **Разбор тохнита на эталоне:** `node scripts/tohnit-eval.mjs ПАПКА` (эталон вне репозитория). Инструмент для Claude — `tools/tohnit/` (`SKILL.md`, `tohnit.py`, `catalog.json`).
- **Правка PDF Ивана** (замена подписей на чертеже тем же шрифтом и цветом) делается разово, вне приложения, через pymupdf.
  Строки заменяются прямо в потоке содержимого: шрифты Type0 Identity-H, коды берутся из ToUnicode, при смене длины поправляется Tm.
  Готовые PDF отдаются Ивану файлом, в репозиторий не кладутся.

## 10. Как мы работаем с Иваном

- **Одна правка за раз.** Иван находит проблему в реальной работе и пишет её по-русски, часто без знаков препинания и с опечатками.
  Мы делаем, проверяем, выкладываем и даём шаги проверки. Следующую правку он присылает после проверки.
- **Не спрашивать «что делать дальше».** Уточняющие вопросы задавать, только когда решение действительно за ним. Лучше вариантами на выбор.
  Если для проверки нужны его скриншоты или файлы, так и сказать.
- **Порядок на каждую правку:**
  1. Разобраться по коду и, если нужно, на копии его данных: последняя резервная копия JSON, которую он присылает.
  2. Сделать и написать тесты в `tests/` на логику из `src/domain`.
  3. `npm test`, `npx vite build`, проверка в Playwright (`?mem=1`) со скриншотами на ширине телефона.
  4. Переводы: новые строки добавить в `src/i18n/src/*.json`, затем `node scripts/i18n-build.mjs`.
     Если меняется поведение, которое видит пользователь, — строка в руководстве (`guide.js`).
  5. Коммит в `main` с понятным русским сообщением (что и зачем), пуш, дождаться выкладки.
  6. Ответить Ивану **коротко**: что сделано (одно-два предложения) и **нумерованные шаги проверки** на телефоне. Без пересказа кода.
- **После его «работает»** — пустой коммит `✅ Проверено Иваном: <что именно>`. Делать его до начала следующей правки, чтобы было видно последнее проверенное состояние.
- **Перед рискованными изменениями:** перенос данных, массовая правка точек, новая версия чертежа.
  Сначала сказать ему, как сохранить проект (☰ → Данные → Резервная копия на Диск) и на каком мы коммите. Если просит — сделать точку отката (раздел 11).
- **Что проверяет Иван:** всё, что видно на телефоне и компьютере, на своих реальных данных.
  - работа без интернета и при слабой сети, скорость запуска;
  - отчёты в дохе (суммы, часы и минуты, иврит);
  - план и чертежи, Google Диск и Таблицы;
  - что ничего не пропало после операций с точками.
  Мы проверяем логику тестами и интерфейс — Playwright в режиме `?mem=1`. Firestore, вход Google, Диск и iPhone до его проверки считаются непроверенными.
- **Стиль ответа.** По-русски, коротко, без жаргона. Действия Ивана — по шагам. Если что-то не работает или не сделано, сказать прямо.
- **Документы в проекте Claude «Менеджер проектов»** (не на GitHub):
  - планы: `План_работ.md`, `Статус_v1.2.md`, `Правки_после_2026-10-17.md`, `Тохнит_без_ИИ_план.md`;
  - `Полевой_журнал_функционал.md` — исходное описание функционала AppSheet и формулы;
  - `apps_script_managers.gs.txt` — старый скрипт таблиц, больше не используется;
  - эталонные файлы точек по чертежам (`точки_*.json`, `*.pdf`).
  Писать туда стоит только то, что пригодится Ивану потом.

## 11. Ветки: release, stable, rollback

Сайт собирается **только из `main`**. Остальные ветки — точки возврата. Ветки используются вместо тегов, потому что теги из облачной сессии не пушатся.

| Ветка | Коммит | Что это |
|---|---|---|
| `release-1.0` | `ff5ad11` | Версия 1.0 «Полевой журнал». **Отдельная история:** при переходе на «один сайт» история `main` начата заново (первый коммит `main` — 23.10.2026), поэтому `release-1.0` не предок `main` |
| `release-1.1` | `fdb4452` | Версия 1.1, один сайт для всех |
| `release-1.2` | `6ff4f43` | Версия 1.2, три языка |
| `one-site` | `7abae5c` | Ветка, в которой делали 1.1. Влита в `main`, хранится для истории |
| `stable-before-tohnit` | `9278998` | 16.10, до встраивания разбора тохнита в приложение (старая история, как `release-1.0`) |
| `stable-2026-10-17-before-edits` | `aaa2f46` | 17.10, всё проверено перед серией правок (старая история) |
| `rollback-2026-11-08` | `3783037` | До переделки работы без интернета |
| `rollback-2026-11-09` | `a0dcc99` | До «Новой версии чертежа» |
| `rollback-2026-11-09b` | `2966523` | Всё проверено: новая версия чертежа, объединение точек, кабели по номеру, свои работы, слабая сеть. **Текущая** |

Зачем это нужно:
- если новая правка что-то сломала, а починить быстро не выходит, можно вернуть сайт к проверенному состоянию;
- `release-*` — версии, на которые можно опереться при восстановлении (ВОССТАНОВЛЕНИЕ.md);
- `rollback-*` Иван просит перед крупными переделками. Он знает их по датам, номера коммитов ещё записаны в памяти Claude.

Как откатывать, только с согласия Ивана:
- не переписывать историю `main` силой. Вернуть содержимое: `git checkout rollback-XXXX -- .`, затем коммит «Откат к …» и пуш в `main`. Сайт пересоберётся сам;
- **код откатывается, а данные в Firestore — нет.** Поля, которые добавили новые версии (`ownWorks`, `cableOverride`, `pos`, `review` у чертежа и т. п.), останутся в данных.
  Старый код их просто не учитывает. Перед откатом попросить Ивана сделать резервную копию на Диск;
- новая точка отката: `git branch rollback-ГГГГ-ММ-ДД <коммит> && git push origin rollback-ГГГГ-ММ-ДД`.
  Если в этот день точка уже есть — суффикс `b`, `c`. Сказать Ивану имя ветки и коммит.

Лишние ветки-отметки можно убрать, только если Иван попросит.
